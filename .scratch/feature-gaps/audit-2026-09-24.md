# Feature gaps and sensible expansions, 2026-09-24

An audit of kardboard at `18c4509`: every package read, the app run locally in dev mode and clicked through at desktop and phone widths. Each item was checked against the code; file references are relative to the repository root, and `server/` means `packages/app/server/src/`, `client/` means `packages/app/client/src/`. Sizes are rough: S is a small pull request, M a few days, L a project.

Items are in four tiers. Tier 1 is things that exist but leave someone stuck or misled. Tier 2 rounds out the Member's loop. Tier 3 is the Agent's toolset. Tier 4 is the Admin and operations. A final section lists what to leave alone.

## Tier 1: fix what is already there

### 1.1 A failed or timed-out Session tells nobody (S–M)

`endSession` records an event and publishes the Card, nothing else: no Comment, no notification, no Mention (`server/services/orchestrator.ts:403-404`). Notification kinds are only `mention` and `card_moved` (`server/db/schema.ts:197`). The Triggers were consumed, so the request is silently dropped and the Card sits in whatever column it was in. The only trace is a line in the collapsed Activity list (`client/routes/board/CardSheet.tsx:591-593`). A Session that exits 0 without commenting or moving the Card counts as `succeeded` (`server/routes/internal.ts:53`), and the recorded reason is only "Container exited with code N"; `OOMKilled` is never read (`packages/runner/src/index.ts:154-161`).

Add: a system Comment on the Card saying the run stopped and why, a notification to the author and the Admin, and a "Try again" control on the Card (at least for the Admin; arguably for the author).

### 1.2 A refused merge leaves the Card stuck in Review (S)

On a merge error other than a changed head or "not mergeable", the Approval stays live and the Agent comments that "an Admin can retry" (`server/services/approvals.ts:194-196`). No retry route exists, and the Card keeps showing "Approved by X… Milo will merge it" with Approve hidden (`CardSheet.tsx:456-461`). PR 14 built the retry but conflicts with `main` since PR 20 (`docs/memory/work/2026-09-14-v1-gaps.md:15`).

### 1.3 kardboard never notices GitHub-side changes (M)

Both GitHub Apps are created with webhooks off (`deploy/github-apps.md:16`), and kardboard reads a pull request only on `set_work_state`, a move to Review, and Approve. Unnoticed: a pull request merged or closed on GitHub, a human pushing to the branch, review comments on GitHub, and a crash between a successful merge and recording Done (`approvals.ts:168-184`; `recoverOnBoot` handles only Sessions, `orchestrator.ts:516-538`). That last one is design-review finding 4's own acceptance case. A Card merged outside kardboard and then dragged to Done is recorded `closed`, not `implemented` (`server/services/children.ts:62-69`), which misleads a parent's `children_done` summary.

Add: a periodic poll of every Card in Review with a pull request (cheaper to build than webhooks), reconciling merged, closed, and head-changed states, and run it at boot.

### 1.4 Approve can merge a red build (M)

`mergePullRequest` never looks at check status (`server/services/github.ts:167-179`), and the Merge app bypasses the ruleset in mode **Always** (`deploy/github-apps.md:55`), so any required checks a repository adds are skipped too. Show check status on the Card and refuse (or warn before) Approve while checks are failing or pending.

### 1.5 A failed start can strand a Card (S)

After three failed start attempts the Triggers return to pending (`orchestrator.ts:317,389-391`), but the pump deliberately skips that Card (`orchestrator.ts:439`) and nothing re-pumps on a timer. On a quiet Board the Card waits until another Session ends or the app restarts. Add a periodic pump with backoff.

### 1.6 A Session's GitHub token expires before its wall clock can (S)

The token is minted once per start and lasts one hour (`server/services/github.ts:95-110`, `orchestrator.ts:201`); the wall clock setting allows up to 240 minutes (`packages/shared/src/index.ts:337`). Pushes fail after an hour. Cap the wall clock at 55 minutes, or add an MCP tool that mints a fresh token.

### 1.7 Nothing moves a Card to In Progress (S)

Neither the server nor the workflow prompt moves a Card into In Progress (`server/services/prompt.ts:61-68`; no `in_progress` in `server/services/` or `server/routes/`). The column the glossary defines as "a Session is implementing" is only filled by the seed data. Add a step after Plan: move the Card to In Progress when implementation starts.

### 1.8 Previews can hang at "Building" and hide a working build (S)

The runner's preview report has no retry (`packages/runner/src/index.ts:323-333`), unlike exit reports, and nothing reconciles Preview rows at boot. Every push restarts app and runner together, so a build in flight during a deploy is lost and the row stays `building` forever. Separately, a rebuild flips status to `building` (`server/services/previews.ts:56`) and the router shows the holding page (`packages/preview-router/src/router.ts:78`) while the old container still serves. The Session never learns a build failed (`request_preview` returns at once, `server/routes/mcp.ts:168-189`), and preview status and error are never on the `Card` type, so Members see the same link whether it is building, broken, or live.

### 1.9 The Review block can mislead (S)

"Ready for your review. Check the preview…" shows for any Card in Review, including one a person dragged there with no pull request or preview (`CardSheet.tsx:220-222,466-478`); Approve stays enabled and the server then refuses (`approvals.ts:136`). There is no confirmation on Approve even though one click merges to `main` and deploys (`CardSheet.tsx:481`).

### 1.10 Activity and attribution show raw or missing data (S)

Five event types have no label and render as the raw string, for example "Milo preview.requested": `preview.requested`, `session.reported` (`server/routes/mcp.ts:179,195`), `card.merged` (`approvals.ts:170`), `card.children_done` (`children.ts:103`), `session.provider_fallback` (`orchestrator.ts:~421`); the label table is `CardSheet.tsx:580-594`. `listMembers` returns only current members and admins (`server/services/boards.ts:61-71`), so a removed Member's comments show as "Unknown", their Cards as "someone", their Approvals as "a member".

### 1.11 Phone problems (S)

Enter posts a comment and Shift+Enter breaks the line (`client/routes/board/composerKeys.ts:32-35`); phone keyboards have no Shift+Enter, so clients cannot write a second paragraph. At 375 px wide the header overflows: the notification bell is clipped and the account avatar is off screen (observed in dev mode, 2026-09-24).

### 1.12 The shallow clone can break "merge the default branch" (S)

Clone and branch fetch both use `--depth=50` (`images/agent/entrypoint.sh:18,35`), while step 5 of the prompt tells the Session to merge the default branch into its own. On a busy repository the merge base can be deeper than 50 commits and the merge fails. Unshallow before the merge, or say so in the prompt.

## Tier 2: round out the Member's loop

- **Show the wait (S).** Nothing appears during the roughly 60-second coalesce window or while a Card waits for a free slot; `pendingRerun` is only set while a Session already holds the Claim (`orchestrator.ts:117-124`). Show "Milo will pick this up shortly" or "waiting for a free slot". Also cap the debounce: `scheduleDispatch` resets its timer on every Trigger (`orchestrator.ts:126-137`), so steady commenting delays the Session indefinitely.
- **Make a Blocked question obvious (S–M).** The Agent's question is one Comment in the thread; there is no pinned "Milo is asking you" callout and no "needs your answer" mark on the tile (`client/routes/board/CardTile.tsx:45-74`).
- **Request changes and Close controls (S).** The only guidance is "Ask for changes in a comment" (`CardSheet.tsx:477`). Closing requires knowing that a move to Done cancels the Session, with no confirmation (`CardSheet.tsx:125-135`). Explicit buttons fit non-technical clients better.
- **Pull request health on the Card (M).** No check status, mergeability, files changed, or line counts; only a pull request link and "Open preview" (`CardSheet.tsx:196-218`). Pairs with 1.4.
- **Tie the Preview to the SHA being approved (S–M).** The preview row stores only the branch (`server/db/schema.ts:210-231`) and the runner clones branch head at request time (`packages/runner/src/previews.ts:121`). If the Session pushes again without requesting a preview, the Member tests old code and approves newer code. Record the built SHA and flag a stale Preview.
- **Attachments when creating a Card (M).** The New Card dialog has no file input or paste handling (`client/routes/board/NewCardDialog.tsx:63-96`); the design says a pasted image becomes an Attachment on a system Comment, and no server path exists for that (`server/routes/api.ts:226-233`). The comment composer has only the paperclip: no paste, no drag and drop, and files over 25 MB are dropped silently (`client/routes/board/Composer.tsx:154-171`).
- **Search, filter, and a Done archive (M).** The toolbar has only New card and the agent pill (`client/routes/BoardPage.tsx:160-198`). Done grows forever in the UI (`server/services/cards.ts:73-80`) and in every Session's `get_board` payload (`server/routes/mcp.ts:58-68`), which costs tokens as the Board ages. Collapse Done to the last N with a "show older" and filter by "mine", "waiting on me", priority.
- **Notification preferences (M).** No email opt-out, per-Board mute, or digest (`server/services/notifications.ts`). Every column move emails the creator (`server/services/cards.ts:250`), so one Card sends three to five emails, and a Blocked question sends two. Email only the moves that ask something of the reader (Blocked, Review, Done), let each User turn email off, mark a Card's notifications read when it is opened (`client/components/Notifications.tsx:23-27`), and render Markdown in email bodies (`server/services/email.ts`). Consider notifying a Card's creator of human Comments on their Card even without a Mention.
- **A first-run explanation (S–M).** An invited client lands straight on the Board (`client/routes/BoardsPage.tsx:29`) with nothing explaining the columns, what the Agent does, or how Approve works. Column hints appear only in empty columns (`BoardPage.tsx:75`).
- **Delete a Comment or Card (S–M).** No delete routes exist (`server/routes/api.ts:213` is PATCH only). A Member who pastes a secret cannot remove it, and the old body also stays in `comment_revisions`. The client already handles `card.removed` (`client/lib/realtime.ts:36`).
- **Smaller polish (S each):** copy-link on a Card (deep links already work, `client/App.tsx:33`); page title with Board and Card names; a reason when a drag is refused (`client/lib/api.ts:140-144`); parent link and child progress ("2/5") on child Cards (`CardSheet.tsx:158`); Done Cards say how they ended; an unsaved-draft guard on the sheet (`CardSheet.tsx:40`); mention list excludes revoked Users (`Composer.tsx:30`); faint text contrast is about 3.4:1 (`client/styles.css:17`); drag announcements read ids (`BoardPage.tsx:202`); a toast for mutations that fail silently (priority change, card-sheet cancel, revoke).

## Tier 3: the Agent's toolset

MCP has eleven tools today (`server/routes/mcp.ts:37-199`).

- **`update_card` (S).** The Agent cannot fix a vague title, tidy a description, or set Priority during intake; Priority is only settable on Cards it creates (`mcp.ts:143`).
- **Board members and handles in `get_board` (S).** The prompt says to Mention the Admin for risky requests (`prompt.ts:72`), but no tool returns members or handles (`mcp.ts:58-68`).
- **Card history on a re-run (S).** `get_card` returns the Card and Comments only: no earlier Session outcomes, activity, Approvals, or children. A re-run after a timeout starts blind.
- **Preview and CI status (S–M).** A `preview_status` tool, and `checks: read` / `statuses: read` on the Session token (`server/services/github.ts:103`) so `gh pr checks` works on private repositories.
- **Prompt additions (S).** Read review comments on GitHub (`gh pr view --comments`); after pushing, wait for and read CI; retry a flaky acceptance command once, then report; when the approval Trigger says "not mergeable", merge the default branch, push, record work state, rebuild the preview, return to Review; treat "LGTM" in a Comment as a pointer to the Approve button, never an Approval.
- **Attachments from the Agent (M).** `post_comment` is text only (`mcp.ts:103-113`), so it cannot post a screenshot of UI work. Pairs with a headless browser in the agent image.
- **Read PDFs (S).** `read_attachment` decodes every non-image as UTF-8 (`mcp.ts:97-99`); client briefs are often PDFs.
- **Claude tool allowlist (S).** `WebSearch`, `TodoWrite`, and `Task` are not allowed (`images/agent/entrypoint.sh:68`).
- **Limit child fan-out (S).** No depth or count limit; a child can split again (`children.ts:26-28`). `create_card` also accepts any Card as parent (`mcp.ts:145`), so closing that "child" wakes an unrelated Card.
- **Less personal data in the container (S).** `get_card` sends the creator's full User record, including email (`mcp.ts:81`); name and handle suffice.

## Tier 4: Admin and operations

- **Alerts (M).** Nothing tells the Admin when a backup fails (`server/services/backup.ts:124`, kept in memory only), start retries run out (`orchestrator.ts:317`), egress refuses a call (`packages/egress/src/proxy.ts:142`), a Codex refresh fails (`proxy.ts:202`), or a Board's Sessions keep failing. An expired Claude token (401) is not recorded at all, since egress and fallback react only to 429 (`server/services/fallback.ts`). The Resend path already exists; an Admin notification kind would cover all of these.
- **Real health checks and kept logs (S).** App and egress `/healthz` always return ok (`packages/app/server/src/index.ts:22`, `packages/egress/src/proxy.ts:149-152`). Compose has no `logging:` block and every push recreates every service, so logs vanish; the 2026-09-22 backup failure is unexplained for that reason (`docs/memory/work/2026-09-14-v1-gaps.md:30`).
- **Sessions tab (S–M).** Rows show the Board, not the Card title (`client/routes/admin/SessionsTab.tsx:79-87`); only the newest 100, no filters (`orchestrator.ts:510-513`); no durations; no re-run of a finished Session; no transcript link from the Card sheet.
- **Usage and cost (M).** Claude's final `result` event carries usage and cost, but `parseTranscript` keeps only turns and duration (`server/services/transcript.ts:100-106`), the `sessions` table has no usage columns, and logs are pruned after 14 days. Codex runs without `--json` (`entrypoint.sh:122-123`). Store tokens, cost, and turns per Session and show per-Board totals. Show Provider limit status from `/limits` in the Agent tab.
- **Board controls (S–M).** A pause switch that stops new Sessions, a per-Board sweep toggle, and "run sweep now". Board archive is out of scope for v1 but is the most likely next need.
- **Users (S).** No way to edit a name, email, or handle, or to change a role after invite. The invite dialog offers "Admin (everything)" (`client/routes/admin/UsersTab.tsx:110-115`), which contradicts the single-Admin glossary. Revoke has no confirmation. `outbound_emails.status` and `error` are never shown and failed emails are never retried (`server/services/email.ts:34,89-93`); invitation delivery is still unverified in production.
- **Audit trail for Admin actions (M).** Invite, revoke, membership, and settings changes record no event (`server/routes/api.ts:302-358`), and Session actions are recorded with no Session id (`mcp.ts:29`), despite the design's "every mutation lands in the event log with its actor".
- **Backups off the disk (S).** Snapshots share the disk with the live database, and `uploads/` is not included (`docs/runbooks/backups.md`). minicore already mounts `/nas/backup`, replicated nightly. Also take a snapshot before migrations run at boot (`packages/app/server/src/index.ts:64-68`), and do one restore drill.
- **Faster Sessions (M).** No dependency caches: every Session re-downloads pnpm, Go, uv, and npm packages (`packages/runner/src/index.ts:208` is the only bind). Per-Board named cache volumes are the biggest speed win available.
- **Container hardening (S–M).** No disk limit for Sessions (`packages/runner/src/index.ts:239-250`), so one can fill the disk holding SQLite; the runner accepts any image (`index.ts:184`); Claude Code is not pinned in the agent image (`images/agent/Dockerfile:33`), which matters given the egress allowlist; one token is shared by all four services including the public-facing preview router (`deploy/compose.yaml:37,60,91,105`).
- **Deploy (S, Admin-only because Sessions cannot push workflow files).** Build images on pull requests with `push: false` so a broken Dockerfile fails before production; path-filter the matrix so a docs-only push does not restart every service (`.github/workflows/ci.yml:39`).

## Later, if a real need appears

- Per-Board environment variables for low-value test credentials (M). Under ADR 0002 and 0003 anything given to a Session is readable by whoever writes Card text.
- Service sidecars such as Postgres or Redis for acceptance commands (L).
- Preview WebSocket support (`packages/preview-router/src/index.ts:47` never handles `upgrade`), preview environment variables, and rebuild on push (S–M).
- API tokens so CI or an error tracker can create Cards (M).
- A read-only Viewer role for clients who should see but not Approve (M).
- A "since you last looked" digest per Board (M).
- A headless browser in the agent image for visual checks (M).
- A per-Member rate limit on Triggers, since every change spends the Admin's subscriptions (S–M).

## Leave alone

Custom Columns, Git hosts other than GitHub, warm pools or git mirrors, a staging stack, comment reactions, and comment history UI. An egress allowlist is an L: ADR 0003 says it "can be added per Board later without changing the Session image", but the egress proxy only handles provider routes and Sessions reach the internet through NAT, so it would need a real forward proxy plus firewall rules.

## Documentation drift found along the way

- `docs/design.md` "Out of scope for v1" still lists transcript viewing, which is built.
- `docs/design.md` names a `finishing` Session state; the schema and shared enum have none (`server/db/schema.ts:141-143`).
- ADR 0003's allowlist claim, above.
- The 14-day Blocked reminder exists only as a sentence in the sweep prompt (`server/services/sweep.ts:83`); nothing records that a reminder was sent, so it may repeat nightly.
- The per-action silent option is exposed only when creating a Card (`NewCardDialog.tsx:15,93`); comment edits cannot be silent (`server/services/comments.ts:129-131`).
