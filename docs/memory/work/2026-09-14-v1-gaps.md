# Remaining v1 gaps

Status: active
Objective: close what the design promised but the first implementation left out, in the order the user prefers. Branch `main`; kardboard is itself a board, so cards on it may drive some of this work.

## Open, needing a user decision first

~~Design-review finding 3, child-Card dispatch.~~ Built 2026-09-15 by the "Child-card dispatch" card, which also settled the decision it was waiting on: an Agent Card starts its own Session only when it has a parent Card and lands in Ready, so an Admin note with no parent still starts nothing; the parent leaves Blocked and gets a `children_done` Trigger when its last child reaches Done; `cards.outcome` records `implemented` (kardboard merged it) or `closed` so the parent can tell a delivered child from a duplicate; waiting Cards are dispatched in Priority, position, then age order. The Admin can still push back on those rules at Approval.
~~Finding 5, Preview cookie scope, and finding 6, workload network isolation.~~ Answered 2026-09-15 by the "Runner-hosted previews" card: a single-use code issued by the app becomes a host-only Preview cookie at the Preview host, cookie and authorization headers are stripped before proxying, a per-Board `preview_epoch` revokes outstanding cookies when membership narrows, and Preview containers sit alone on a `kardboard_preview` network with no binds, no capabilities, and resource limits. The decision left for the user is only the hostname shape, below.

~~Provider fallback on usage-limit errors (design Q25).~~ Built 2026-09-15 by the "Provider fallback" card: the egress proxy records a 429 per provider with the reopening time its headers named and serves it at `/limits`; the app skips a provider whose window is still shut on dispatch, and on a failed Session whose provider refused during its life it writes a `provider_fallback` Trigger and re-dispatches on the other one. `sessions.fallback_from` makes it one hop. On by default, Admin switch in the agent tab.
